# Image persistence: one id, one file, one availability rule

**Status.** Proposed. Nothing in this document is implemented yet; every statement about the current tree was read off the working copy at the line cited, and §8 names the two places where the brief that commissioned this document and the tree disagree instead of smoothing the difference.

**Scope.** Pasted images, end to end: the browser paste that produces a data URL, the WebSocket envelope that carries it, the ingest boundary that turns it into an id, the adapter that turns an id back into bytes for the model, and the HTTP route that turns an id back into a thumbnail. Chat text, tool output, and file attachments other than images are out of scope.

## 1. The defect, stated once

An image in this tree has four identities and no owner. The durable store names the bytes with a minted 32-hex id and writes them atomically to `<vault>/workspaces/<ws>/images/<id>.<ext>` (`agent/core/image_files.py:235-288`, id shape at `agent/core/image_files.py:109-122`). The process-wide cache holds the same bytes under the same id but applies its own capacity policy and substitutes text for a miss (`agent/core/image_store.py:64-71`). The thumbnail route reads the disk only and infers which workspace to read from by a cascade that starts at a persisted session record and falls back to whatever a live bridge happens to hold (`web_ui/backend/session_routes.py:722-747`). The browser keeps a fourth copy — the original data-URL preview — in a module-level registry that binds a preview to a message row by media type, query and declared dimensions (`web_ui/frontend/src/utils/pastedImagePreviews.js:196-219`).

**The question "is this image available?" therefore has four answers, and each layer is locally correct.** The disk answers for the route, the cache answers for the adapter, the live bridge answers for a session that has not been saved yet, and the preview registry answers for the current tab. No component is wrong in isolation; what is wrong is that none of them is authoritative, so availability degrades from a fact into an observer-dependent opinion. The user-visible shape of that opinion is a dashed 80×60 box labelled "Image" in place of the picture they pasted (`web_ui/frontend/src/components/chat/MessageBubble.jsx:276-285`, styling at `web_ui/frontend/src/styles.css:380-396`), and the model-visible shape is a placeholder string in the prompt (`llm_providers/openai_compatible.py:193-202`), and the two can occur while the bytes are still on disk.

**The durable layer is already the complete one, which is why this is a deletion problem rather than a build problem.** `agent/core/image_files.py` owns the id namespace, the media-type whitelist, atomic writes, a reference scanner that reports whether it saw everything, and a sweep that refuses to delete a referenced file even to satisfy a byte budget (`agent/core/image_files.py:1-20`, `agent/core/image_files.py:363-441`, `agent/core/image_files.py:540-636`). The two layers above it re-decide pieces of that design and disagree with it about capacity, identity and lifetime. The ruling in §4 keeps the durable layer as it is and removes the re-decisions.

The image path is small: five Python modules, one provider adapter, four frontend files. Its own naming is inconsistent enough that the same concept is spelled three ways in three modules, which is the mechanical reason the layers drift.

**The budgets are already enumerated, and they do not line up with each other.** Per turn the ingest accepts at most four images, six mebibytes each and ten mebibytes of decoded total, with an explicit note that the per-image cap alone bounds nothing (`web_ui/backend/image_ingest.py:47-56`). The cache holds 32 entries or 96 MiB, whichever binds first (`agent/core/image_store.py:64-68`). The workspace holds 256 MiB with a 24-hour orphan age (`agent/core/image_files.py:89-95`). So a workspace can legally hold thousands of images that the cache can show at most 32 of, and the seam between those two numbers is exactly where the failure in §3 F3 lives.

**The tests are already written against both layers, which is why the deletion in §5 is a test edit as well as a code edit.** Eight test modules cover the path: `tests/test_pasted_images_transport.py` (564 lines), `tests/test_pasted_images_end_to_end.py` (286 lines), `tests/test_session_image_route.py` (428 lines), `tests/core/test_image_files.py` (706 lines), `tests/core/test_image_store.py` (217 lines), `tests/providers/test_openai_image_blocks.py` (447 lines), `tests/test_image_sweep_schedule.py` (256 lines) and `tests/test_logging_image_redaction.py` (259 lines). The two that assert cache behaviour survive every rule in §4 except R4, and the one that pins the placeholder string verbatim (`tests/core/test_image_store.py:210`) survives unchanged because the constant outlives the cache that used to produce it.

## 3. Six consequences

Each failure below is a consequence of the structure in §1, not a separate defect with a separate fix. That is the point of listing them: six independent symptoms are what a single unbounded authority looks like from six directions.

**F1 — The id in a transcript can name no file.** Ingest attempts the durable write only when a workspace is known, logs the failure and continues, and then mints an id anyway (`web_ui/backend/image_ingest.py:221-238`). The metadata it returns is shape-identical either way (`web_ui/backend/image_ingest.py:242-247`), so a transcript cannot tell a durable reference from a cache-only one. The workspace is known only when the client connected with a `?project=` query parameter, because the handshake pins `_handshake_ws_id` inside that branch (`web_ui/backend/server.py:1581-1592`) and passes it straight through on both turn kinds (`web_ui/backend/server.py:1686-1688`, `web_ui/backend/server.py:1741-1743`). A tab that never sent the parameter therefore produces ids that resolve in the cache and 404 at the route, and nothing in the transcript records which kind it got. The two halves of the path are asymmetric about this, and the asymmetry is the finding: the read side refuses a client-supplied workspace by written policy — "A ``workspace_id`` query parameter is deliberately NOT accepted: cookie auth proves *some* session, and a client-supplied workspace is the client-claim class." (`web_ui/backend/session_routes.py:613-615`) — and derives the workspace from the session's own state instead (`web_ui/backend/session_routes.py:789`), while the write side depends on the client's `?project=` hint to make the same binding and reads its absence as a degraded mode rather than a refusal, even though the socket's own path already defaults to the project root (`web_ui/backend/server.py:1571-1573`, `web_ui/backend/server.py:1585-1592`, `web_ui/backend/image_ingest.py:221-238`). Containment exists and does not close the gap: a load whose probed workspace differs from the handshake pin is refused outright (`web_ui/backend/server.py:2929-2939`), which stops one connection from switching scope, but a connection that pinned nothing stays unbound for the life of the socket, so every image it ingests is a cache-only id and the refusal never fires.

**F2 — The route and the adapter can disagree about the same turn, and both are right by their own rules.** The route reads the disk and never touches the cache (`web_ui/backend/session_routes.py:789-799`); the adapter reads the cache and never touches the disk (`llm_providers/openai_compatible.py:180-192`). For an image ingested while the workspace was bound, both succeed. For an image ingested without one, the adapter sends the picture to the model while the thumbnail route has nothing to serve; for an image whose cache entry has been evicted, the route serves the picture while the adapter sends placeholder text. The second case is the one users notice: the picture is on their screen, the model is told it cannot see the screenshot, and the answer is confidently wrong about a screenshot it was never given.

**F3 — Availability is decided by an eviction loop that has never read the transcript.** The cache evicts the least recently used entry, preferring entries whose refcount is zero, and drops the in-memory copy only (`agent/core/image_store.py:118-138`). That is a correct cache policy and an incorrect availability policy: the persisted transcript is untouched by eviction, so the same id is simultaneously "referenced by history, file present on disk, unavailable to the model". The adapter's own docstring states the consequence plainly — an image whose bytes are gone is replaced by placeholder text "so the model is told it cannot see the screenshot instead of the turn failing" (`llm_providers/openai_compatible.py:120-131`) — which is the right degradation over a cache that should not have been deciding the question.

**F4 — The route's correctness depends on process memory, and a restart changes the answer for the same id.** The route reads history live-first because a freshly ingested id is appended to the running session object and only reaches disk at end-of-turn save (`web_ui/backend/session_routes.py:757-781`). The workspace resolver then prefers the persisted record and falls back to the first live bridge that holds a workspace (`web_ui/backend/session_routes.py:735-747`). Both branches are described as "process-side state", and neither is reachable from a request body, which is true and is the problem: whether a thumbnail loads depends on which process is answering and how far along the turn is. A reload, a second worker, or the same session opened in a fresh server is a different availability rule for the same immutable bytes.

**F5 — Dimensions are hearsay, and they are the field used to bind a preview.** The ingest coerces any non-integer dimension to zero (`web_ui/backend/image_ingest.py:80-86`), a bare data-URL string entry yields zero for both dimensions (`web_ui/backend/image_ingest.py:172-176`), and the durable store records no dimension at all — `agent/core/image_files.py` has no width or height in its API. The frontend's matcher then treats zero as agreement with anything (`web_ui/frontend/src/utils/pastedImagePreviews.js:181-187`) and claims a pending preview on media type, query and those dimensions (`web_ui/frontend/src/utils/pastedImagePreviews.js:196-219`). The single field that could distinguish two pastes of similar images is a client claim with a wildcard value, so the matcher's confidence is not measurable from anything it checks.

**F6 — Three deletion policies guard one object, and no two of them agree about what a reference is.** The cache collector releases store entries whose ids the session no longer references after pruning, and refuses to delete durable files on purpose because it runs inside every save and would race the file it is writing (`agent/core/image_gc.py:214-261`, call site at `session/store.py:466-474`). The close path unlinks durable files, but only for ids the closing session tracked, and only when the workspace reference scan completed (`agent/core/image_gc.py:113-188`). The sweep deletes unreferenced files past the 24-hour age and then trims to the byte budget, never touching a referenced file (`agent/core/image_files.py:540-636`, scheduled at `web_ui/backend/server.py:864-882` with the fail-safe skip for an incomplete scan). Three policies, three reference authorities — post-prune in-memory history, the closing session's tracked set, the persisted transcripts — and the only reason this has not produced a lost image yet is that each of them errs toward keeping bytes.

## 4. The ruling: six rules

**R1 — The id is minted by the durable store, once, and no id leaves ingest without a file behind it.** `image_files.save_image` already mints and writes (`agent/core/image_files.py:235-288`); ingest calls it and lets a failure fail the turn. The workspace-unbound branch is not a degraded mode to be tolerated — it is a caller that has not satisfied the precondition, and the honest response is to refuse the image rather than to mint an id nothing can resolve. Deleting the fallback at `web_ui/backend/image_ingest.py:236-238` is the whole of this rule; the cache-only id disappears with it.

**R2 — A transcript entry carries the id string and nothing else.** Today a message's `images` list holds metadata dicts (`agent/core/agent.py:1588`, produced at `web_ui/backend/image_ingest.py:242-247`), and downstream code has grown three-shape tolerance to cope: a resolver that accepts a string, a dict with `id`, and a legacy dict with `image_id` (`agent/core/image_gc.py:56-71`), plus two walkers that inherit that tolerance (`agent/core/image_gc.py:191-211`, `agent/core/image_files.py:463-476`). One shape deletes the tolerance, and with it the class of bug where a persisted row is well-formed for one reader and not for another.

**R3 — Media type and dimensions are properties of the file, derived when it is read.** The store already answers media type from the extension (`agent/core/image_files.py:350-360`) against a three-entry whitelist (`agent/core/image_files.py:100-107`), so a client-declared type adds nothing but a disagreement gate (`web_ui/backend/image_ingest.py:188-193`). Dimensions either get measured at ingest and stored beside the file, or they leave the identity entirely; what they must not do is remain the field that binds a preview to a row while their unknown value is spelled zero and read as a wildcard (`web_ui/frontend/src/utils/pastedImagePreviews.js:181-187`).

**R4 — Availability is a filesystem fact with exactly one observable answer.** The route's single 404 for every miss already implements this on the read side, including the deliberate refusal to distinguish a deleted file from another workspace's file (`web_ui/backend/session_routes.py:691-719`, `web_ui/backend/session_routes.py:794-799`). The rule extends it to the adapter: it resolves bytes through the same durable read, so the placeholder becomes reachable only when the file is genuinely gone. The cache may remain as a performance detail, but it may not be the authority, which means its eviction can no longer change what a model sees. This is the rule that makes the placeholder string an honest report rather than a capacity artifact.

**R5 — The workspace is bound once per session and every reader takes the same binding.** The cascade that resolves it — path cache, metadata sidecar, registry, payload field, legacy path parity (`session/store.py:668-700`) — exists to answer one question cheaply, and it answers it five ways. With R1 making a bound workspace a precondition of ingest, a session record that names no workspace is a session whose images nobody can find, and refusing at save time is cheaper and more honest than a read-time fallback to a live bridge. The route keeps its store-first query (`web_ui/backend/session_routes.py:735-742`) and loses the bridge loop beneath it (`web_ui/backend/session_routes.py:743-747`).

**R6 — Deletion has one authority: the workspace's persisted transcripts.** This authority already exists and already refuses to act on a partial view: `scan_workspace_references` returns the ids it saw and whether it saw everything (`agent/core/image_files.py:363-441`), the close path keeps every candidate when the scan is incomplete (`agent/core/image_gc.py:158-188`), the sweep deletes nothing referenced even to satisfy a byte budget (`agent/core/image_files.py:602-616`), and the scheduled sweep skips a workspace it could not read completely (`web_ui/backend/server.py:866-877`). The rule adds only the negative half: no capacity policy may delete bytes, so the cache's LRU stops being a lifetime decision and the 32-entry ceiling becomes a bound on memory rather than on what the user can still see.

## 5. What is deleted

The ruling is mostly subtraction. Each row names what leaves, where it lives, and what answers the question afterwards.

| Metadata dicts in `images` | `web_ui/backend/image_ingest.py:242-247` | id strings (R2) |
| Three-shape id resolver | `agent/core/image_gc.py:56-71` | one shape, one walker (R2) |
| Client-declared media type check | `web_ui/backend/image_ingest.py:188-193` | extension-derived type (R3) |
| Client-declared dimensions | `web_ui/backend/image_ingest.py:80-86`, `web_ui/backend/image_ingest.py:172-181` | measured at ingest, or absent (R3) |
| Adapter reads the cache | `llm_providers/openai_compatible.py:180-192` | durable read by id (R4) |
| Eviction as an availability decision | `agent/core/image_store.py:118-138` | filesystem fact (R4) |
| Live-bridge workspace fallback | `web_ui/backend/session_routes.py:743-747` | one bound workspace (R5) |
| Live-first history read as a correctness device | `web_ui/backend/session_routes.py:770-781` | id on disk before it is referenced (R1, R5) |

| Placeholder-on-miss thumbnail | `web_ui/frontend/src/components/chat/MessageBubble.jsx:276-285` | keep for genuine misses only |

**What survives, deliberately.** The cache module's placeholder constants, because a placeholder for a genuinely deleted file is still correct and is pinned by test (`tests/core/test_image_store.py:210`, `tests/providers/test_openai_image_blocks.py:178-187`). The single-404 discipline, because it is the read side of R4 already implemented. The reference scanner, the sweep, and the fail-safe skip, because they are R6 already implemented. The preview-first source order in the thumbnail (`web_ui/frontend/src/components/chat/MessageBubble.jsx:275`) may stay as an optimistic render, but it stops being load-bearing: the durable URL is the answer, and the preview only arrives sooner.

**What this costs.** The turn path gains a disk read where it used to hit a dictionary. That read is a `stat`-plus-`open` on a local file whose name is already validated against `IMAGE_ID_RE` (`agent/core/image_files.py:109-112`) and whose resolution is confined to the workspace directory (`agent/core/image_files.py:291-318`); it is the same read the thumbnail route already performs per request. The alternative — keeping a cache in front of it — is legitimate only if the cache is allowed to answer "miss" without the model being told something false, which is what R4 forbids.

## 6. How it is proven

**The invariants are testable as statements about the tree, not about behaviour under load.** An id in a persisted transcript resolves to exactly one file in exactly one workspace. Ingest never returns an id for which no such file exists. No code path other than the reference scan decides that a referenced file may be deleted. The adapter's wire output contains an image block if and only if the file is readable. The thumbnail route's 404 set and the adapter's placeholder set are the same set.

**Two of the six rules have no test to delete, only tests to add.** R4 and R5 change the answer for cases that are currently unrepresented: an image ingested with no bound workspace, and the same id read from a second process. Both need a test that fails today. Evidence for the first is already assembled by the transport tests, which drive ingest directly (`tests/test_pasted_images_transport.py:63`) and by the end-to-end test that asserts the placeholder is absent when bytes are present (`tests/test_pasted_images_end_to_end.py:165`, `tests/test_pasted_images_end_to_end.py:191`) — the missing case is the same assertion with the workspace parameter omitted.

**The documentation gate is part of the proof.** Every citation in this document resolves to an existing file with in-bounds lines, checked by `scripts/verify_doc_citations.py`, which the repository's own suite runs. A design statement that cites a module that does not exist is a design statement nobody can check, which is why §8 records the two places where the commissioning brief named files that are not in this tree.

## 7. Rollout order

**Step 1 — Measure before deleting.** Add the failing test for an ingest with no bound workspace and for a second-process read of an existing id. Until these exist, R4 and R5 are opinions. Nothing in this step touches product code.

**Step 2 — Make the file the only readable source.** Point the adapter at the durable read and keep the cache in place but unused on the read path. This is the only step that changes behaviour for users mid-flight, and it changes it in the safe direction: more images become visible to the model, none become invisible.

**Step 3 — Close the id namespace.** Delete the cache-only fallback and require a bound workspace in ingest. Every new id now names a file. Old transcripts keep resolving, because ids minted without a file simply 404 — the same answer they already get from the route, now also from the adapter.

**Step 4 — Narrow the entry shape.** Stop writing metadata dicts, keep every reader tolerant for one release so existing transcripts still load, then remove the tolerance and the resolver it needs. Two releases, one shape.

**Step 5 — Delete the preview registry.** The frontend stops claiming previews, the echo handler stops merging them, and the store slice that carried them goes with them. This is the last step because it is the only one where a regression is visible as a blank thumbnail rather than an unavailable image, and by then the route is the only source of thumbnails and is already the authority.

**Step 6 — Retire the cache's lifetime role.** Keep the module if it still earns a hit rate on the wire path; delete its eviction policy's consequences by making a miss mean "the file is gone". If the hit rate does not justify the module, delete the module.

**Ordering constraints.** Step 2 must precede step 3: making the adapter read the disk is what turns the fallback from a safety net into dead code, and deleting dead code is a review that does not require re-reasoning about availability. Step 4 must precede step 5: the preview matcher's dimension comparison is the only consumer of the metadata dict's dimensions, so removing the matcher first leaves a field with no reader and no test. Step 6 is independent and can be deferred indefinitely at the cost of one dictionary lookup per image per turn.

## 8. Boundaries, and what this document does not claim

**Two paths named in the commissioning brief do not exist in this tree.** The brief cites web_ui/frontend/src/components/session/SessionTab.jsx; there is no `components/session/` directory at all, and the component that performs the preview attach is `web_ui/frontend/src/components/SessionTab.jsx` (`web_ui/frontend/src/components/SessionTab.jsx:724-731`), which is what every citation above uses. The brief also cites agent/providers/openai_compatible.py; there is no `agent/providers/` directory, and the adapter that resolves ids to image blocks is `llm_providers/openai_compatible.py` (`llm_providers/openai_compatible.py:101-205`). Both citations were probably written against an older layout, but a citation that names a missing file cannot be verified by anyone, so the correction is recorded here rather than silently applied.

**The brief's failure (a) names the right defect through the wrong mechanism, and the true mechanism is worse.** `?project=` exists, but it is a WebSocket handshake parameter on the endpoint signature (`web_ui/backend/server.py:1561`) with its own documented comment block (`web_ui/backend/server.py:1523-1531`) and its own workspace pinning (`web_ui/backend/server.py:1581-1592`); the REST image route has no project parameter at all and is not scoped by one (`web_ui/backend/session_routes.py:750-751`). So "the route takes a client-supplied project and trusts it" is false as stated. What is true is that the two halves of the path disagree about client input: the route refuses a client-supplied workspace by written policy (`web_ui/backend/session_routes.py:613-615`) while the write path requires the client's hint to be present and treats its absence as a degraded mode rather than a refusal (`web_ui/backend/server.py:1581-1592`, `web_ui/backend/image_ingest.py:221-238`), so the bytes are lost to the client's silence rather than to its lie. The fix follows from that: there is no client-supplied workspace path to confine on this route, only an inference to remove, and an unbound session that must be refused at ingest instead (R1).

**This document does not claim the current code is unreachable in its failure modes without evidence.** What is established is that the paths exist and that the two layers disagree by construction (`web_ui/backend/session_routes.py:789-799` reads disk only; `llm_providers/openai_compatible.py:183` reads cache only). What is not established is how often a real deployment reaches the disagreement — that requires the workspace-unbound case to be exercised against a live server, which §7 step 1 is designed to produce and which no test in this tree currently does.

**Publishing is one line in the ignore file, and two readers read that same line.** `docs/*` is ignored (`.gitignore:143`) and each published document needs its own negation line, a policy stated in the ignore file itself (`.gitignore:187-188`); this document's line is `!docs/design-image-persistence.md` (`.gitignore:146`), added in the same change as the document. Both consumers of that line live in this tree: git decides what ships, and the codebase indexer builds its exclusion spec from the same file — it gathers every ignore pattern (`agent/knowledge/codebase_indexer.py:113`), assembles them into one pathspec (`agent/knowledge/codebase_indexer.py:144`), and skips any file the spec matches (`agent/knowledge/codebase_indexer.py:200`) — so a document without its line is written but never indexed, and the failure is silent because nothing else notices it. Publishing does not, however, buy this document a citation gate: the only citation-check step in CI verifies one document, `docs/CONTRACTS.md` (`.github/workflows/contract-gate.yml:98`), and the comment above that step records the design spec as a known gap (`.github/workflows/contract-gate.yml:93-96`), while a bare invocation of the checker defaults to `docs/design-worker-lifecycle.md` (`scripts/verify_doc_citations.py:98`). The gate for this document is therefore a command someone has to run, `scripts/verify_doc_citations.py --doc docs/design-image-persistence.md`, not a step that runs itself.

**The file was renamed to `docs/design-image-persistence.md` from the draft's IMAGE_PERSISTENCE_DESIGN.md, following the design-document naming this tree already publishes (`.gitignore:145` re-includes `docs/design-streaming-canonical-ir.md`, `.gitignore:185` re-includes `docs/design-auth-boundary.md`).**

**The rule set is deliberately narrower than the problem.** It says nothing about how images should be sized for a model's context budget, nothing about transcoding or downscaling, and nothing about the retention policy a user might want for their own pastes. Those are real questions and each of them would add a policy that could disagree with R6. They belong in their own document, after the tree has one authority for "does this image exist" rather than four.
