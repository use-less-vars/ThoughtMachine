### Template for User-Customizable Dockerfile

**`resources/default_dockerfile.txt`** (978 bytes) — fallback template for the unified runtime image (`infra/resource_container_manager.py`):

```dockerfile

**Note**: This template uses `requirements.txt` (host file with web server packages), NOT `docker/requirements-docker.txt`. This means user-custom containers get FastAPI/uvicorn/etc., while the executor container gets ML packages.

## 3. Host vs Container Discrepancy

| Category | Host (`requirements.txt`) | Container (`requirements-docker.txt`) |
|----------|--------------------------|---------------------------------------|
| Web framework | `fastapi`, `uvicorn`, `pydantic-settings` | — |
| HTTP/WS client | `httpx`, `websockets`, `python-multipart`, `aiofiles` | — |
| Docs | `markdown` | — |
| Testing | `pytest` | — |
| **ML/AI Bloat** | — | `sentence-transformers`, `chromadb`, `langchain`, `langchain-community` |
| Shared (16) | `openai`, `pydantic`, `python-dotenv`, `fast-json-repair`, `libcst`, `tiktoken`, `docker`, `modelcontextprotocol`, `mcp`, `PyYAML`, `anthropic`, `sseclient`, `beautifulsoup4`, `lxml`, `pathspec`, `tree-sitter` | Same |

### The Bloat Problem

`docker/requirements-docker.txt` includes 4 packages that pull in **~2GB+** of GPU/ML dependencies:

| Package | Pulled-in Dependencies | Approx Size |
|---------|----------------------|-------------|
| `sentence-transformers` | `torch` (526MB), `transformers` | 550MB+ |
| `chromadb` | `onnxruntime` (19MB), `opentelemetry-*`, `kubernetes`, `grpcio` | 80MB+ |
| `langchain` | `langchain-core`, `langgraph`, `langsmith` | 20MB+ |
| `langchain-community` | `aiohttp`, `sqlalchemy` | 15MB+ |
| **NVIDIA CUDA deps** (via torch) | `nvidia-cudnn` (366MB), `nvidia-cublas` (423MB), `nvidia-cusolver` (201MB), `nvidia-cusparse` (146MB), `nvidia-nccl` (206MB), `nvidia-cufft` (214MB), `triton` (198MB) | ~2GB+ |

**Total bloat**: ~3GB+ of unnecessary GPU/ML packages in the executor container, which is designed for **code execution sandboxing**, not ML training.

**Root cause**: `docker/requirements-docker.txt` was split from `requirements.txt` but retained ML packages (sentence-transformers, chromadb, langchain) that were added for RAG/vector-store features on the host. These were never intended for the executor container.

## 4. GUI Workspace Panel: Dockerfile Source

### Web UI Rebuild Mechanism

**`web_ui/backend/server.py`** line 1875:
- WebSocket command `"rebuild_container"` is handled by calling `docker_executor.rebuild_container()`
- This triggers a background rebuild of the executor Docker image

### GUI Flow

```
User clicks "Rebuild Container" in Workspace Panel
    → WebSocket "rebuild_container" event
    → server.py handler
    → docker_executor.rebuild_container(workspace_path)
    → Background thread:
        1. Stop & remove existing container
        2. _build_image(nocache=True)
           → Builds from docker/executor.Dockerfile
           → Installs docker/requirements-docker.txt
        3. _ensure_container()
           → Creates fresh container from new image
    → Status reported back via WebSocket
```

## 7. Container Persistence Analysis

| Property | Value |
|----------|-------|
| Container lifecycle | Long-running (`tail -f /dev/null` CMD) |
| Execution model | `docker exec` into running container |
| Rebuild trigger | Web UI "rebuild container" button, or agent tool `build=True` |
| Image tag | Derived from workspace path hash |
| Container per workspace | Single container, reused |
| Stale detection | Yes — `verify_container_integrity()` checks config matches |
| Ephemeral per-command | No — container persists between commands |

### Container Content Persistence

- `/workspace` directory inside container is **ephemeral** (not a mount)
- The host workspace is **not mounted** into the container
- Files must be explicitly copied in/out via Docker API
- `pip install --user` packages persist inside the container across commands
- Container is **stopped and removed** on rebuild

### Security Model

- Network access: controlled by session permissions (security gate)
- Filesystem access: controlled by session permissions
- User runs as `agent` (UID 1000), not root
- No `sudo` available

## 9. Dependency Unification Plan

### Current Problem

`docker/requirements-docker.txt` and `requirements.txt` have diverged. They share 16 packages but each has unique packages. The container file has **no business** including ML packages.

### Recommended Approach

Create a **minimal** `docker/requirements-docker.txt` containing only what the executor container actually needs for tool execution:

```

```

Remove from container:
```
- sentence-transformers  (pulls torch + nvidia-* → ~2GB)

- langchain              (pulls langchain-core, langgraph → ~20MB)

**Estimated savings**: ~2.5GB+ container size reduction.

#### Option B: Unified requirements.txt (host) + minimal requirements-docker.txt (container)

#### Option C: Shared core + overlay files

- `requirements-core.txt` (16 shared packages)
